# RunRace NSM 코치 로드맵

> 상태: N0·N2 완료, N1은 페이스 축만 통과(수요 축 미검증) · **N3 미착수** — 처방 스펙·수치는 코드가 단일 출처(`frontend/src/lib/nsm.ts`), 이 문서는 결정 로그
> 작성 2026-06-30 · 갱신 2026-07-28 (별도 문서였던 "NSM 개선 계획"을 여기로 흡수)
> 관련: [roadmap.md](roadmap.md) (경쟁 축 — N3에서 P3 크루와 결합) · [product-positioning.md](product-positioning.md)
> 전제: NSM(노르웨이식 싱글 방법론)은 **런갤(러닝 마이너 갤러리) 수요 신호에서 출발한 훈련 코칭 버티컬**. 경쟁 축과 별개지만 N3에서 소셜로 합류한다.

---

## 배경

- 런갤에서 *"nsm 앱 만들어봐 / nsm 러닝프로그램 찾아봤는데 없더라"* 수요 신호 발견. 현재는 수기 *"딸깍 표"*(엑셀/표로 페이스·일정 계산)로 대체 중 — 제대로 된 앱 부재 = 빈 공간.
- NSM 코어는 구현 완료(N0). 다음은 **검증 → 개인 추적 → 소셜 확장** 순.

## 전체

| 단계 | 내용 | 성격 | 상태 |
|---|---|---|---|
| **N0** | NSM 코어 | 빌드 | 완료 |
| **N1** | 검증 — 크루/런갤에 노출, 페이스·수요 확인 | **비-빌드, 게이트** | 페이스 축만 통과 → 코어 재캘리브레이션 (수요 축 미검증) |
| **N2** | 이행률 추적 — 세션 완료 기록 → 주간 진척 | 빌드 (개인 리텐션) | 완료 |
| **N3** | NSM 소셜 — 크루·라이벌 NSM 도전 + 이행률 리더보드 | 빌드 (경쟁 P3 결합) | **미착수** |

### 순서 근거
- **N1(검증) 먼저**: 코어가 안 먹히면(페이스 틀림·수요 없음) 위 빌드가 통째로 헛심. 런갤 신호는 *가설*일 뿐 검증이 아님.
- **N2 전에 N1**: 까다로운 청중이라 페이스 정확도·실수요 확인이 투자 게이트.
- **N3는 N2 위에**: 이행률 데이터가 있어야 리더보드가 성립. 경쟁 로드맵 **P3(크루 레이스)** 와 합류점.

## N1 — 검증 (페이스 축만 통과, 2026-07)

이 게이트의 통과 기준은 두 축이었다 — ① 처방 페이스의 정확도, ② 수요.

**① 페이스 정확도 — 통과.** 방법은 **문서 대조**였다: 출력 페이스를 런갤 NSM 자료 11건(*"딸깍 표"* 포함)과 맞춰봤다.
결과적으로 처방 오차가 드러나 **코어 보정을 먼저 실행**했다(`da21e20`, Phase 1+2).

**② 수요 — ⚠️ 검증 기록이 없다.** 원안은 YRC 크루·런갤 NSM러에게 실사용 의향을 듣는 것이었으나,
그렇게 했다는 흔적이 커밋·문서 어디에도 없다. 실제로 했다면 결과를 여기 적고, 안 했다면 **N3 착수 전 남은 게이트**로 취급할 것.
(LacTrace·TheThresholdApp 대조도 원안의 계획 대상이었을 뿐, 실제 대조 기록은 런갤 자료 쪽뿐이다.)

보정된 것(전부 구현 완료 — 현행 값은 `nsm.ts`·`NSM_BAND_CONFIG`·`frontend/tests/nsm.test.ts`가 정확함):
세션 간 페이스 간격 확대, SHORT/LONG 거리 기반 → 시간 기반 렙, 주간 볼륨 밴드 도입(렙 수·휴식·sub-T 일수 스케일링), 후반 렙 가속 유도 큐 제거, ~4주 재측정 배너, 역치 검증 밴드 프론트/백엔드 정합.

→ SHORT/LONG을 **시간 기반**으로 바꾼 이유: 거리 기반이면 **느린 러너일수록 렙 시간이 팽창**한다
(5K를 30분에 뛰는 러너 기준 short 6분·long 19분이 되어 처방이 무너진다). "km가 더 직관적"이라며 되돌리자는 제안은 이 사유로 기각한다.

### 결정: 0.88 앵커는 건드리지 않는다

`THRESHOLD_VO2_FRACTION = 0.88`(≈LT2) **변경은 기각**하고 세션 오프셋으로만 맞췄다.
근거: 이 앵커가 내는 역치값이 런갤 기준 페이스 표와 이미 일치했다(10K 45:00 → 277초/km = 4:37, 표의 3분 렙 밴드 4:33–4:37의 느린 끝 = 보수적). 어긋난 것은 앵커가 아니라 **세션 간 간격**이었다. 앵커를 흔들면 VDOT 파생값 전체가 같이 움직여 검증된 기준점을 잃는다.
→ 이후 페이스가 커뮤니티와 어긋나면 **오프셋 3개를 먼저 의심**하고 앵커는 마지막에 본다.

## N2 — 이행률 추적 (완료 · 8968708, 95d8b67)

런 종료 시 sub-T 세션 자동 로깅 → 주간 진척·성장 리포트.
로그 모델은 **세션 단위 append-only**로 결정 — 플랜은 유저당 1행 upsert라 요일을 바꾸거나 취소하면 과거 스케줄이 사라지고, 매일 뛰는 방법론이라 `workout_session` 유무로도 복원이 안 된다. 근거 전문은 `V55__nsm_session_log.sql` 코멘트, 재측정 추이는 `V59__nsm_retest_log.sql` 참조.
심박 가드는 health-sync 풀릴 때 (병렬 트랙, [health-sync-design.md](health-sync-design.md))

## N3 — NSM 소셜 (빌드, 경쟁 P3 결합) — 미착수

크루/라이벌이 같이 NSM → 이행률 리더보드. 앱의 기존 소셜 강점(라이벌·레이스)과 결합.
- **크루 NSM 챌린지**: 같은 주간 sub-T 이행률 경쟁
- **라이벌 NSM**: 라이벌 세션 완료 알림(도발 푸시 인프라 재활용)
- 경쟁 로드맵 **P3(크루 레이스)** 와 합류 — 자동 집계가 단체전 마찰을 줄임

현재 crew·rivals 코드에 NSM 참조는 0건. N2의 완료 데이터가 쌓였으므로 착수 전제는 갖춰졌다.

## 커뮤니티 NSM 기준 — 코드로 옮기지 않은 것

런갤 자료에서 추린 기준 중 아래는 아직 앱에 반영되지 않았다(나머지 — 세션 3종 시간·휴식, 볼륨 티어별 렙 수, ~4주 재측정, 더운 날 5~15초/km 완화 — 는 전부 코드에 있음).

- **sub-T 총량은 주간 볼륨의 15~25% 상한.** 현재 코드의 도즈 경고는 밴드별 절대 분(`doseMinMin`/`doseMaxMin`)만 비교한다 — 실제 주행 볼륨 대비 비율은 보지 않는다.
- **400m·5K 페이스 렙 금지.** sub-T는 "짧은 렙일수록 빠르고 긴 렙일수록 느리게"이지 인터벌이 아니다. 렙 길이를 더 짧게 하자는 요청이 와도 이 선은 넘지 않는다.
- **회복 기준**: "다음날 이지런 가능, 이틀이면 재훈련 가능"이 정상. 마지막 렙은 안정적이어야 하고 *"조금 더 할 수 있을 것 같은"* 느낌으로 여유를 남기고 끝낸다. 세션 설계·큐 문구를 손볼 때의 판정 기준.

## 하지 말 것

1. **캘린더 기반 rep 자동 증가(주차 진행) 금지** — 완료 데이터 게이트 없이 달력만으로 rep를 올리면 NSM이 막으려는 피로 누적을 앱이 유발한다. 하려면 반드시: 보수적 onramp에서 시작해 위로 + 완료/피드백 게이트.
2. **이미 적용된 마이그레이션 수정 금지** — 로컬 DB에 즉시 적용되어 체크섬이 깨진다. 항상 새 버전.
3. **Toss 러닝코치와 "5K→스케줄 생성" 정면 경쟁 포지셔닝 금지** — 유통에서 진다. 차별화 축: ① 검증된 정확한 처방(N1 보정이 전제) ② 런 중 라이브 렙 가이드(중기: 오디오/햅틱 큐로 워치 대비 약점 보완) ③ crew↔NSM 소셜 레이어(N3).
