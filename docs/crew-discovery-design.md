# 크루 발견 + 가입신청(승인제) 설계

> 상태: **구현 완료** (설계 2026-07-21 / 구현 커밋 `fd09b9d`) — 마이그레이션 V45 + API·화면 전량 반영. 이후 다중 이미지(V46, `cfbce6f`), 창설일(V47, `755cdb4`)로 확장.
> 스펙 정본은 코드다. 이 문서는 **왜 그렇게 정했는가**를 남기는 결정 로그.
> 관련: [roadmap.md](roadmap.md) (P3 크루 축) · [product-positioning.md](product-positioning.md)
> 배경: 러닝라이프(runninglife.co.kr/crew) 크루 디렉터리를 벤치마크. 단 러닝라이프는 **오프라인 모임 디렉터리**(SNS로 이탈 가입)라, 핵심 정보(장소·정기런)만 선택 필드로 차용하고 가입은 **앱 내 승인제**로 재설계.

---

## 1. 목표

당시 크루 발견 목록은 `이름 + 인원수`뿐이고, 가입은 **초대코드 6자만** 가능(닫힌 모델). 이걸:

1. **목록 리치화** — 대표이미지(선택) + 지역 + 인원 + 정기런 요약
2. **지역 필터** — 시도 17개 + 온라인
3. **공개 크루 상세 페이지** — 소개·이미지·정기런 정보 + 가입신청 CTA
4. **승인제 가입** — 목록/상세에서 **가입신청 → 리더 승인/거부** (초대코드는 즉시가입으로 병행 유지)
5. **푸시 알림** — 신청 접수(→리더), 승인/거절(→신청자, 거절 사유 선택 포함)

원칙: 초대코드=신뢰 즉시가입, 신청=공개 발견 경로(리더 게이트). 발견 기반 성장을 열되 난입은 리더가 막는다.

## 2. 확정된 결정 (사용자)

| # | 결정 |
|---|---|
| 1 | 리더에게 "새 가입신청" 푸시 **넣음** |
| 2 | 지역 = **시도 17개**(+ 온라인) |
| 3 | 이미 크루 있으면 신청 **불가** → "먼저 지금 크루를 나가야 해요" 안내 |
| 4 | 여러 크루 동시 신청 **허용**, 한 곳 승인 시 나머지 pending **자동 취소** |
| 5 | 정원 찼으면 신청 버튼 **"정원 마감" 비활성** + 승인 순간 정원 재확인 |
| 6 | 거절 후 **24h 쿨다운**(같은 크루) |
| 7 | 신청 시 **한마디(선택)** 첨부 |
| + | 공개 **크루 상세 페이지** 신설(카드 → 탭 → 상세 → 신청) |

결정 4의 전제: 1인 1크루다. 그래서 동시 신청은 열어두되(신청자가 여러 곳을 두드릴 수 있어야 발견이 의미가 있다) 한 곳이 확정되는 순간 나머지는 무효로 정리한다.
결정 5의 후단(승인 순간 재확인)이 필요한 이유: 신청과 승인 사이에 정원·소속 상태가 바뀔 수 있다.
결정 6은 거절당한 신청자의 재신청 도배를 리더가 감당하지 않게 하는 장치. 쿨다운은 상태를 따로 저장하지 않고 최근 REJECTED 시각에서 계산한다(§3).

## 3. 데이터 모델 — 결정만

스키마 정본: `backend/src/main/resources/db/migration/V45__crew_discovery.sql`(+ V46 `image_urls`, V47 `founded_at`). 컬럼별 의미는 해당 파일의 `comment on` 참조.

- **`region`은 필수** — 필터가 성립하려면 빈 값이 없어야 한다. 기존 크루는 `ETC`(기타)로 백필하고 필터 목록 맨 뒤에 노출, 리더가 설정에서 고치도록 유도.
- **지역 코드 = 시도 17 + `ONLINE`(온라인/전국) + `ETC`(기타·백필 sentinel).** 경기도만 남/북 2분할(인구 1위 + 한강 기준 생활권 분리), 나머지는 시도 레벨 유지. 코드 목록은 `frontend/src/lib/crewRegion.ts`.
- **저장은 코드, 표시는 프론트 라벨맵** — ko가 정본, en은 로마자, ja/zh/es는 en 폴백. 지역은 한국 특화라 비-ko 사용이 드물어 번역 투자 가치가 낮다.
- **`intro`(공개 소개)와 `notice`(회원용 고정공지)는 별개 필드** — 읽는 대상이 다르다(비회원 vs 크루원).
- **쿨다운에 전용 컬럼을 두지 않는다** — `(crew_id, user_id)`의 최근 REJECTED `decided_at`으로 계산. 같은 사실을 두 곳에 저장하지 않기 위함.
- **중복 신청 차단은 DB 부분 유니크 인덱스로** — 애플리케이션 가드와 별개의 마지막 방어선(`status = 'PENDING'`일 때만 유니크).

## 4. 신청 생명주기 (상태 머신)

```
         apply                approve
  (없음) ─────▶ PENDING ─────────────▶ APPROVED  (+CrewMember 생성, 타 pending 자동취소)
                  │  ├── reject ─────▶ REJECTED  (+reject_reason, 24h 쿨다운 시작)
                  │  └── cancel ─────▶ CANCELED  (신청자 스스로 철회)
                  └── (타 크루 가입 시 자동) ─▶ CANCELED
```

CANCELED로 들어오는 경로가 둘인 것이 결정 4의 귀결이다: 신청자가 직접 철회하거나, 어떤 경로로든(승인·초대코드) 크루에 들어가는 순간 남은 PENDING이 일괄 정리된다.

가드 순서와 에러 코드(`already_in_crew` / `crew_full` / `already_pending` / `apply_cooldown` / `apply_rate_limited` 등)는 `CrewService.apply/approve/reject/cancelApplication` 참조. 상태 전이 테스트는 `CrewServiceTest`.

## 5. API·화면

엔드포인트는 전부 `CrewController`(`/api/crews` 하위, 가입신청은 `/api/crews/join-requests/{id}/…`)에, 화면은 `frontend/src/app/crew/` 아래에 있다 — 발견 목록 `_components/CrewDiscovery.tsx`, 공개 상세 `_components/CrewDetailContent.tsx`, 리더 인박스 `_components/JoinRequestInbox.tsx`, 내 신청 현황 `_components/MyApplicationsSection.tsx`.

코드만 봐선 안 드러나는 결정:

- **멤버 로스터는 비공개** — 인원수만 노출. 프라이버시 판단이고, 러닝라이프도 명단은 안 깐다.
- **발견 목록 정렬은 인원 많은 순** — 빈 크루가 위로 올라오면 발견 목록의 신뢰가 깨진다. 후속으로 "최근 활동순" 고려 여지.
- **공개 상세는 비회원도 조회 가능** — 발견이 로그인 뒤에 갇히면 유입 경로로 못 쓴다. 로그인 상태일 때만 내 신청상태·쿨다운을 얹어 CTA를 분기한다.
- **`/crew/{id}` 정적 export 우회** — 동적 라우트를 템플릿 하나(`/crew/view`)로 만들고 nginx가 `/crew/{숫자}`를 거기로 넘긴다. id 상한 없이 직접 접속을 열기 위한 타협(`frontend/src/lib/crewRoute.ts`, `infra/nginx/runrace.conf`).

푸시 3종(`crew.apply.received` / `approved` / `rejected`)은 기존 인프라 재활용 — `SystemPushHistory` + `device_token`(FCM), 수신자 `lang_cd`·`push_enabled` 준수. 문안은 `messages*.properties`, 발송은 `CrewNotifications`.

## 7. 설계 시 미결 3건 — 해소

1. **크루 이미지 공개 서빙 방식** — 별도 공개 엔드포인트(`GET /api/crews/{id}/image`)를 만들지 않고 **URL 동봉**으로 갔다. 설계 초안의 `image_key`(S3 비공개 키, `challenge_prize` 패턴 재활용)를 버리고 공개 URL을 그대로 담는 `image_url text`로 바꾼 것. 크루 이미지는 애초에 공개 정보라 게이트를 둘 이유가 없고, 업로드는 공용 `/api/uploads` 경로를 재사용한다.
2. **`region` 백필** — 최다 크루 지역 추정 없이 `ETC` 고정(단순).
3. **승인/거절 후 요청 행 보존** — 삭제·만료 정리 없이 유지(감사 목적). 별도 purge 작업 없음.

## 8. 남은 미구현

- **발견 목록의 이름 검색** — 설계에는 `discover?query=`와 검색창이 있었으나 지역 필터만 구현했다. (`/api/crews/search?query=`는 도전장 상대 고르기 전용이라 별개다.) 크루 수가 지역 필터로 훑기 버거워지면 그때 붙인다.
